# 技术路线与测试报告

## 1. 架构

数据流固定为：只读块设备 → 故障场景与扫描计划 → 分区/主备结构识别 → The Sleuth Kit 文件系统元数据主引擎 / 雨痕原生元数据补充 / PhotoRec 内容扫描兜底 → 结果去重与校验 → 另一物理盘输出与恢复报告。UI 不直接解析磁盘，恢复模型、规划、检查点、校验与队列执行位于 `Recovery.Core`。

- `RecoveryPlanFactory`：将“误删除”、“快速格式化/RAW”和“分区丢失”转换为明确扫描阶段。TSK 与雨痕原生元数据扫描是两个独立阶段，可分别记录完成状态。
- `RecoveryCapabilityRegistry`：文件分类、PhotoRec family、图片预览、文本预览、结构预检和恢复后校验的唯一能力源。文本格式仅允许元数据恢复和可读性检查，不进入 PhotoRec 无边界雕刻。
- `ScanCheckpointV3`：原子保存源介质多点指纹、分区布局、故障场景、执行选项、扫描目标、阶段状态、位置和候选索引。原生阶段按字节位置续扫，TSK/PhotoRec 按阶段边界续作；中断 PhotoRec 阶段会重新导入可独占打开且连续两次大小稳定的暂存文件。
- `RecoveryCandidateIndex`：分批接收候选，先按大小、扩展名和快速指纹分组，只对碰撞组计算完整 SHA-256；精确相同的副本合并显示，并保留备用元数据恢复上下文。
- `RecoveryBatchExecutor` / `RecoveryReportWriter`：单文件故障不中止队列，系统性目标盘故障才停止后续项；每批生成 JSON 和 CSV 逐项报告。

- `SleuthKitEngine`：固定官方 The Sleuth Kit 4.15.0，以 `fls` 递归读取已删除文件元数据并由 `icat` 按元数据地址恢复。进程参数使用 `ArgumentList`，不经过 Shell；Windows 中文输出按原始字节检测 UTF-8/CP936，保留 Unicode 原路径；同路径、大小和时间的历史目录项合并显示但保留备用元数据地址。
- 成熟引擎分工：TSK 是 NTFS/exFAT/FAT 元数据与原名恢复主引擎；PhotoRec 7.2 是文件系统元数据丢失后的格式特征兜底；雨痕旧解析器只承担 TSK 失败回退及全盘旧 MFT、exFAT 孤儿条目等补充扫描，完成真实镜像对照后再逐步缩减。

- `IBlockDevice`：统一物理盘和镜像文件；Windows 物理盘使用 `CreateFileW(GENERIC_READ)`，不提供写方法。真实设备读取采用 `SetFilePointerEx + ReadFile` 和 8 MiB 只读缓存，避免 NVMe RAID 驱动与普通文件长度 API 不兼容。
- `WindowsStorageEnumerator`：使用同样的 `GENERIC_READ` 句柄兼容 NVMe RAID 驱动，并读取设备型号、容量、总线、可移动属性和 TRIM 能力。
- `PartitionScanner`：MBR/GPT/整盘文件系统，采用 `ulong` 处理大容量偏移；可选顺序搜索并严格解析丢失的NTFS/exFAT/FAT32引导记录。
- `NtfsScanner`：读取 Boot Sector，从 `$MFT` 记录 0 的 runlist 定位完整 MFT，处理 FILE 记录 fixup、文件名和无名数据属性。
- `NtfsScanner` 深度模式：从有效 MFT 末端开始，对后续 512 MiB 区域按 FILE Record 大小对齐扫描；只有通过签名、USA fixup、记录号、序列号、属性边界和数据簇范围校验的记录才进入候选集。旧目录记录用于重建 Unicode 原路径。
- `NtfsScanner` 全盘旧 MFT 模式：以 8 MiB 流式窗口和跨块重叠区搜索整个卷中的 `FILE` 记录，不假设记录相对卷起点按 1024 字节对齐；仅排除当前 MFT 有效长度对应的物理区间（保留预分配尾部搜索），并对候选执行扇区对齐、USA fixup、记录号、属性和数据范围校验。
- `NtfsBitmapAccessor`：分页读取 `$Bitmap`，区分未分配、可能复用、全零/TRIM。
- `ExFatScanner`：按微软 exFAT 规范解析 Boot、活动 FAT、根目录与子目录条目集；识别清除 InUse 位的 File/Stream/FileName 条目，恢复 Unicode 原名、路径、精确长度、首簇和连续/FAT 链分配。
- `ExFatScanner`深度模式：以8 MiB窗口顺序读取整个簇区，按32字节边界寻找删除条目集；校验File/Stream/FileName组合、集合校验和、Unicode名称、首簇和64位长度，并按名称、长度和物理数据偏移去重。
- `Fat32Scanner`：解析BPB、FAT、活动/删除目录项和LFN条目，重建Unicode原名、父目录和簇序列；簇链清除时明确采用连续簇推断并降低质量评级。
- `PausableBlockDevice`：在下一次只读块读取边界暂停，继续后保持扫描器内存状态，不从头重扫。
- exFAT 分配位图按 64 KiB 页面批量检查；物理盘缓存根据请求自适应为 64 KiB 至 8 MiB，避免大量候选的小随机读取被放大。
- `SignatureCarver`：流式分块扫描并保留跨块重叠区，避免把整盘载入内存。
- `DiskImager`：4 MiB 顺序读取失败后拆分为 64 KiB，再递归拆至逻辑扇区；只对真正不可读扇区填零，原子保存检查点/坏区地图并计算最终 SHA-256。既有镜像、状态或介质指纹不一致时保守拒绝覆盖。
- `RecoveryDestinationSafety`：把目标卷映射到物理盘号，阻止源盘回写。

## 2. 介质与文件系统策略

机械硬盘、SSD、U 盘、SD/TF 卡和移动硬盘在核心层都作为只读块设备处理，因此介质接口不会改变扫描算法。差异主要是：SSD/部分 U 盘支持 TRIM，删除后控制器可能已经返回全零；机械盘通常保留旧扇区直到覆盖。

NTFS、exFAT 和 FAT 使用 TSK 元数据恢复；NTFS、exFAT 与 FAT32 另有雨痕只读原生补充扫描，因此元数据仍存在时可保留原文件名、目录与精确长度。exFAT 连续文件直接按簇区间恢复；非连续文件在删除后的 FAT 链仍保留时可以重组，簇链被清除时保留原名和大小并降级为 `Poor`。元数据不存在时才降级为 PhotoRec 内容扫描，且不承诺原名。

## 3. 容量路线

- GPT 使用 64 位 first/last LBA；文件偏移使用 `ulong`，进入 Windows API 前检查 `long.MaxValue`。
- 已以不分配 16 TiB 实体空间的稀疏块设备模型验证 16 TiB 级 GPT 末端分区数学。
- 实际目标限定为小于 16 TiB，远低于当前寻址上限；实际吞吐受 USB/SATA 控制器与坏扇区数量影响。
